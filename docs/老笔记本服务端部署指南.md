# 老笔记本服务端部署指南

> 目标：把 5 个全栈应用在后端跑在老笔记本上，通过 **Cloudflare Tunnel** 以
> `xxx.你的域名.com` 的形式暴露到公网，供 [mariana.dev 主站](https://github.com/MarianaBunnyJump)的
> 「日常工具」页外链访问。主站本身是纯静态，托管在 Vercel / Cloudflare Pages，
> **不**跑在这台笔记本上。

文档基于各项目 2026-09 的实际代码梳理（启动脚本、端口、.env 均已逐一核对）。

## 0. 架构与端口总览

```
访问者 ──https──▶ Cloudflare 边缘
                    │  cloudflared 隧道（笔记本出站连接，无需公网 IP / 端口映射）
                    ▼
              老笔记本（Windows，建议 8GB+ 内存）
              ├── sentinel   :8787   Node 直跑（pm2 托管）
              ├── ppt-web    :47600  vite preview（pm2 托管）
              ├── ppt-api    :47610  uvicorn（pm2 托管）+ ppt-worker（无端口）
              ├── labu       :7302   Docker（前端已打进镜像，自包含）
              ├── wxlearn    :80     Docker（Caddy 托管 H5 + 反代后端 + MySQL）
              └── dl         :8000   uvicorn（pm2 托管，FastAPI 同端口托管前端）
```

| 子域名（示例） | 本地端口 | 服务 | 运行方式 |
|---|---|---|---|
| `sentinel.你的域名.com` | 8787 | 哨兵站 · AI 资讯监控 | pm2 · Node |
| `ppt.你的域名.com` | 47600 → 47610 | AI PPT 工作台（前端/API） | pm2 · uv + vite |
| `labu.你的域名.com` | 7302 | AI 修图智能体 | Docker · compose deploy profile |
| `learn.你的域名.com` | 80 | AI 闯关学习（H5） | Docker · Caddy + FastAPI + MySQL |
| `dl.你的域名.com` | 8000 | 协传 · 视频下载器 | pm2 · uvicorn |
| （可选）`s3.你的域名.com` | 7313 | LabuLabuTV 的 MinIO 对象存储 | Docker |

## 1. 环境准备（一次性）

笔记本假设为 **Windows 10/11 64 位**。若是 Linux 笔记本，见文末「附 A」。

### 1.1 基础软件

| 软件 | 版本建议 | 安装方式 | 用途 |
|---|---|---|---|
| Node.js | 20 LTS | [nodejs.org](https://nodejs.org) 安装包 | sentinel、PPT 前端 |
| Python | 3.12+ | [python.org](https://www.python.org) 安装包（勾选 Add to PATH） | dl 后端 |
| uv | 最新 | `pip install uv` | PPT_Helper / 通用 Python 运行器 |
| Git | 最新 | [git-scm.com](https://git-scm.com) | 代码同步 |
| Docker Desktop | 最新 | [docker.com](https://www.docker.com/products/docker-desktop/)（需启用 WSL2） | labu、wxlearn、PPT 基础设施 |
| pm2 + pm2-windows-startup | 最新 | `npm i -g pm2 pm2-windows-startup` | Node/Python 进程托管与开机自启 |
| cloudflared | 最新 | `winget install Cloudflare.cloudflared` | 隧道 |

安装完 pm2 后注册开机自启：

```powershell
pm2-startup install
```

### 1.2 Docker Desktop 设置

- Settings → General → 勾选 **Start Docker Desktop when you sign in**。
- 老笔记本内存吃紧的话，在 `C:\Users\<用户名>\.wslconfig` 里限制 WSL2 内存：

  ```ini
  [wsl2]
  memory=4GB
  ```

### 1.3 让笔记本"永不掉线"

1. **电源计划**：设置 → 电源 → 接通电源时「永不睡眠」「永不关闭硬盘」；关闭快速启动可减少休眠异常。
2. **BIOS**：开启 *Restore on AC Power Loss*（来电自动开机），这样家里跳闸恢复电后机器自己爬起来。
3. **自动登录**（可选）：`netplwiz` → 取消"必须输入用户名和密码"→ Docker Desktop 与 pm2 服务才能在重启后自动随会话拉起。
4. **Windows 更新**：设置"活动时间"，避免白天自动重启；至少每月手动重启一次装更新。

### 1.4 验证环境

```powershell
node -v; python --version; uv --version; docker --version; pm2 -v; cloudflared --version
```

## 2. 逐个部署服务

> 建议顺序：先跑通 **sentinel**（最简单，练手 pm2）→ **dl**（纯 Python）→
> **PPT_Helper**（Docker 基础设施 + pm2 混合）→ 两个纯 Docker 应用（labu、wxlearn）。
> 每个服务本地验证通过后，再进入第 4 章接隧道。

### 2.1 哨兵站 sentinel-station（端口 8787）

```powershell
cd E:\apps\sentinel-station
npm ci
copy .env.example .env      # 首次部署：然后编辑 .env
notepad .env
```

`.env` 关键项（把开发机 `E:\13_AIPrj\Android_InfoGet\sentinel-station\.env` 拷过来最省事）：

| 变量 | 说明 |
|---|---|
| `PORT=8787` | 监听端口，保持默认 |
| `AI_PROVIDER` / `OPENROUTER_API_KEY` / `DEEPSEEK_API_KEY` | AI 供应商与密钥 |
| `OPENROUTER_MODEL` | 监控判定用模型 |

启动并注册到 pm2：

```powershell
pm2 start npm --name sentinel -- start --cwd E:\apps\sentinel-station
pm2 save
```

**验证**：浏览器打开 `http://localhost:8787`，页面有内容且控制台日志无
`aiKey=MISSING` 即成功。数据落在 `data\` 目录（SQLite）。

### 2.2 协传 · 视频下载器（端口 8000，单端口托管前后端）

```powershell
cd E:\apps\protocol-video-downloader\backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
notepad .env
```

`.env` 关键项（开发机 `backend\.env` 可直接拷贝改）：

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | AI 摘要 / 问答 |
| `JWT_SECRET` | 改成随机长字符串：`python -c "import secrets;print(secrets.token_hex(32))"` |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` / `STRIPE_PRICE_ID_MONTHLY` | 支付，不对外收款可先留空 |
| `FRONTEND_URL` | 填 `https://dl.你的域名.com` |

构建前端并启动（FastAPI 检测到 `frontend\dist` 会自动托管，单端口搞定）：

```powershell
cd E:\apps\protocol-video-downloader\frontend
npm ci
npm run build

cd ..\backend
pm2 start .venv\Scripts\python.exe --name dl-api -- -m uvicorn main:app --host 0.0.0.0 --port 8000
pm2 save
```

**验证**：`http://localhost:8000/api/health` 返回 `{"status":"ok",...}`；
首页能打开；B 站/抖音解析各试一条。

### 2.3 AI PPT 工作台 PPT_Helper（前端 47600 / API 47610）

结构：Docker 起 PostgreSQL + Redis 基础设施 → pm2 起 API、worker、前端。

```powershell
cd E:\apps\PPT_Helper
docker compose up -d          # postgres :47660 + redis :47661

cd server
copy .env.example .env
notepad .env
uv sync                       # 安装 Python 依赖（uv.lock 锁定版本）
uv run alembic upgrade head   # 建表

cd ..\web
npm ci
npm run build                 # 构建前端静态产物
```

`server\.env` 关键项：

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | 指向 `postgresql://ppt:ppt@127.0.0.1:47660/ppt_helper` |
| `REDIS_URL` | `redis://127.0.0.1:47661/0` |
| `JWT_SECRET` | 改成随机长字符串 |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 大模型供应商 |
| `LLM_MOCK` | 生产设为 `false` |
| `STORAGE_DIR` | PPT 产物目录，如 `E:\apps\PPT_Helper\storage` |

注册 3 个进程到 pm2（`uv` 找不到时用 `where uv` 查绝对路径替换）：

```powershell
cd E:\apps\PPT_Helper\server
pm2 start uv --name ppt-api -- run uvicorn app.main:app --host 0.0.0.0 --port 47610
pm2 start uv --name ppt-worker -- run arq app.worker.settings.WorkerSettings

cd E:\apps\PPT_Helper\web
pm2 start npx --name ppt-web -- vite preview --host 0.0.0.0 --port 47600
pm2 save
```

> `vite preview` 会继承 `vite.config.ts` 里的代理配置：47600 的 `/api` 请求自动转发到
> 47610，所以前端 API 调用同源，无需改 CORS。

**验证**：`http://localhost:47610/docs` 能打开 Swagger；`http://localhost:47600`
能打开界面并完整生成一份 PPT（验证 worker 在干活）。

### 2.4 AI 修图智能体 LabuLabuTV（端口 7302，全 Docker）

`deploy` profile 会把前端构建进镜像，uvicorn 在容器内监听 7302，一个 compose 全搞定。

```powershell
cd E:\apps\LabuLabuTV
copy .env.example .env
notepad .env                     # 按注释填密钥；数据库/Redis/S3 地址 compose 已注入，勿重复填
docker compose --profile deploy up -d --build
```

首次启动会下载 CV 模型到 `cv_models` 卷（u2net 等），耐心等几分钟。

**⚠️ 公网访问必须处理的一处**：`docker-compose.yml` 里 `S3_PUBLIC_ENDPOINT` 默认是
`http://localhost:7313`（MinIO），生成结果的图片直链会指向用户本机 → 公网用户图片全部裂图。
两种解法选一：

1. **推荐**：在第 4 章隧道里加一条 `s3.你的域名.com → http://localhost:7313`，
   然后把 compose 中 `app` 和 `worker` 的
   `S3_PUBLIC_ENDPOINT` 改为 `https://s3.你的域名.com`，`docker compose --profile deploy up -d` 重建。
2. 同时把 MinIO 的 `MINIO_ROOT_PASSWORD` 从默认的 `retouch_dev` **改成强密码**——它一旦暴露公网就是存储桶。

**验证**：`http://localhost:7302` 打开编辑器，抠一张图走完整个流程；
确认返回的图片 URL 能在浏览器直接打开。

### 2.5 AI 闯关学习 WxAILearn（端口 80，全 Docker）

compose 里已含 Caddy（托管 H5 + 反代 API）+ FastAPI + MySQL 8.0，开箱即用。

```powershell
cd E:\apps\WxAILearn\miniapp
npm ci
npm run build:h5                 # 生成 H5 静态产物（Caddy 容器挂载 dist）

cd E:\apps\WxAILearn
notepad .env
```

`.env` 必填项（compose 文件头部注释即模板）：

```ini
DEEPSEEK_API_KEY=sk-xxx
SITE_ADDRESS=:80
MYSQL_PASSWORD=<强密码1>
MYSQL_ROOT_PASSWORD=<强密码2>
```

> **`SITE_ADDRESS` 必须填 `:80`**，不要填域名——HTTPS 由 Cloudflare 隧道终结，
> 填域名会让 Caddy 尝试向 Let's Encrypt 签证书（80/443 没直接暴露公网，会失败）。

```powershell
docker compose up -d --build
```

**验证**：`http://localhost/` 打开 H5 首页，答一组题确认 `/api` 通了、
MySQL 建表成功（看 `docker compose logs backend` 无报错）。

> 若 80 端口被占（`netstat -ano | findstr :80`），改 compose 里 Caddy 的端口映射为
> `"8080:80"`，后续隧道指向 `http://localhost:8080` 即可。

## 3. 进程自启汇总

| 层 | 机制 | 操作 |
|---|---|---|
| pm2 进程（sentinel / ppt-api / ppt-worker / ppt-web / dl-api） | pm2-windows-startup | 每次改动后 `pm2 save`；重启后自动恢复 |
| Docker 容器（PPT 基础设施 / labu / wxlearn） | compose 里 `restart: unless-stopped` | 已内置，只要 Docker Desktop 随登录自启 |
| 隧道 | Windows 服务方式安装（见下章） | 系统级自启，无需登录 |

常用命令：

```powershell
pm2 ls                 # 进程状态
pm2 logs ppt-api       # 看日志（Ctrl+C 退出）
pm2 restart all
docker compose ps      # （在各项目目录下）容器状态
```

## 4. Cloudflare Tunnel：把 5 个服务暴露成公网子域名

前提：已有一个域名（如 `yourdomain.com`），并把 DNS 托管到 Cloudflare
（免费套餐即可，在域名注册商处把 NS 记录改为 Cloudflare 提供的地址）。

### 4.1 登录并创建隧道

```powershell
cloudflared tunnel login           # 浏览器授权，选择你的域名
cloudflared tunnel create mariana-lab
```

### 4.2 写配置文件

编辑 `C:\Users\<用户名>\.cloudflared\config.yml`：

```yaml
tunnel: mariana-lab
credentials-file: C:\Users\<用户名>\.cloudflared\<隧道ID>.json

ingress:
  - hostname: sentinel.你的域名.com
    service: http://localhost:8787
  - hostname: ppt.你的域名.com
    service: http://localhost:47600
  - hostname: labu.你的域名.com
    service: http://localhost:7302
  - hostname: s3.你的域名.com        # LabuLabuTV 图片直链（见 2.4）
    service: http://localhost:7313
  - hostname: learn.你的域名.com
    service: http://localhost:80
  - hostname: dl.你的域名.com
    service: http://localhost:8000
  - service: http_status:404        # 兜底，必须保留
```

### 4.3 生成 DNS 记录并注册为系统服务

```powershell
cloudflared tunnel route dns mariana-lab sentinel.你的域名.com
cloudflared tunnel route dns mariana-lab ppt.你的域名.com
cloudflared tunnel route dns mariana-lab labu.你的域名.com
cloudflared tunnel route dns mariana-lab s3.你的域名.com
cloudflared tunnel route dns mariana-lab learn.你的域名.com
cloudflared tunnel route dns mariana-lab dl.你的域名.com

cloudflared service install        # 注册为 Windows 服务，开机自启、无需登录
```

**验证**：在手机流量（非家 WiFi）下访问 `https://sentinel.你的域名.com`，
能打开且浏览器显示有效证书即成功。

> 主站不要走这台笔记本：PersonalSite 交给 Vercel / Cloudflare Pages，
> 绑定根域 `你的域名.com` 或 `www.`。笔记本只承载 5 个全栈应用。

### 6.4 异常自查顺序

1. `pm2 ls` / `docker compose ps` —— 谁挂了？
2. `pm2 logs <name>` / `docker compose logs --tail 100 <服务>` —— 报什么错？
3. 服务都在但外网不通 → `cloudflared service status`，看隧道进程；
   Cloudflare Zero Trust 控制台看隧道在线状态。
4. 全部不响应 → 多半睡眠了或 Windows 更新重启了，远程唤醒不了就回家按电源吧。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 端口被占用 | `netstat -ano | findstr :8787` 找 PID，`tasklist | findstr <PID>` 看是谁 |
| `docker compose` 报错连不上 Docker | Docker Desktop 没启动，手动开一次并检查自启设置 |
| sentinel 启动报 `better-sqlite3` 二进制错误 | Node 大版本和开发机不一致，`npm rebuild better-sqlite3`；建议统一 Node 20 LTS |
| pm2 找不到 `uv` / `npx` | 用绝对路径：`where uv`、`where npx`，把路径写进 pm2 启动命令 |
| labu 图片直链裂图 | 没按 2.4 改 `S3_PUBLIC_ENDPOINT`，或 s3 子域隧道没加 |
| wxlearn 起不来报 80 端口冲突 | compose 里把 Caddy 映射改成 `"8080:80"`，隧道指向 8080 |
| 隧道下 AI 流式输出卡住 | Cloudflare 原生支持 SSE/WebSocket；确认中间没有再套一层 nginx 之类开了缓冲的代理 |
| 内存不足、容器被杀 | `.wslconfig` 调大/调小内存；把不常用的服务（如 labu 的 worker）按需停用 |
| 电费/噪音心疼 | 5 个服务对老笔记本负载很低，风扇基本不转；半夜可只留 sentinel + wxlearn |

## 附 A：Linux 笔记本速查

若笔记本装的是 Ubuntu 等 Linux 发行版，整体更简单：

- Docker 用官方 `docker-ce` + `docker compose plugin`，无需 Docker Desktop / WSL2；
- pm2 换成 **systemd**：每个服务写一个 `*.service`（`ExecStart` 对应本文各启动命令），
  `systemctl enable --now <name>`；
- cloudflared 直接 `apt` 安装后 `cloudflared service install`；
- 其余步骤（.env、compose、隧道 ingress、main.js）完全一致。
